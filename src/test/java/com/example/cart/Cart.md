## 1. 요구사항 — 도메인 규칙(0층) + User Story

> 원천: `docs/calculate-cart-requirements.md`
> **숫자의 정본은 아래 "검산 전개" 하나다.** 단계 2 Gherkin의 `Examples` 표를 비롯한
> 이후 모든 수치는 이 전개에서 옮겨온 **파생 뷰**이며, 각자 다시 계산하지 않는다.

### 도메인 규칙 (0층)

- 기본 규칙
    - 장바구니는 0개 이상의 라인을 가진다. 라인 = (상품, 단가, 수량), 수량 ≥ 1.
    - **상품 합계** = 모든 라인의 (단가 × 수량) 합.
    - **배송비**는 주문당 고정 3,000원. 단, 빈 장바구니(라인 0개)는 배송비도 0원.
    - 모든 금액은 원 단위 정수이며 음수가 될 수 없다.
- 특별 규칙 — 할인 적용 순서가 불변식
    - 적용 순서: **상품 합계 → 쿠폰 할인 → 마일리지 차감 → 배송비 합산**.
      이 순서는 불변식이며 바꾸면 결과가 달라진다(쿠폰이 배송비를 깎지 못한다는 점이 순서로 표현된다).
    - **쿠폰 할인(1단계)** — 상품 합계에서만 차감한다.
        - 쿠폰 금액이 상품 합계를 초과하면 상품 잔액은 0원에서 멈춘다. **초과분은 소멸**한다(이월·환급 없음).
        - 예: 상품 합계 3,000원에 5,000원 쿠폰 → 상품 잔액 0원, 쿠폰 초과분 2,000원 소멸(고객 손해 효과).
    - **마일리지 차감(2단계)** — 쿠폰 적용 **후 잔액** 기준으로 차감한다.
        - ① 먼저 상품 잔액에서 차감한다.
        - ② 상품 잔액이 0원에 도달하면, 남은 마일리지는 **배송비에서 추가 차감**한다.
        - ③ 배송비도 0원에 도달하면, 그 이상의 마일리지는 **사용되지 않는다**
          (소멸이 아니라 **미사용** — 차감 상한. 쿠폰 초과분의 소멸과 구별된다).
        - 따라서 마일리지 사용액의 상한 = (쿠폰 적용 후 상품 잔액) + 배송비.
    - **최종 결제 금액** = 상품 잔액 + 배송비 잔액. 항상 ≥ 0.
    - 미사용 마일리지(상한 초과분)는 계산 결과에 노출하지 않는다 — 최종 결제 금액만 반환한다(사용자 결정).
- 입력 유효성 — 계산기가 검증 책임을 가진다(사용자 결정)
    - 수량 < 1, 단가 < 0, 쿠폰 < 0, 마일리지 < 0 등 명백히 잘못된 입력은 계산기가 거부한다(예외).
    - 마일리지가 고객의 보유 잔고를 초과하는지, 쿠폰이 유효한지 등 **외부 상태 의존적 검증**(잔고 조회, 쿠폰 유효기간 등)은 이 스토리 범위 밖 — 상위 계층(장바구니 조회/주문 흐름)의 책임이다.

#### 검산 전개 (숫자의 정본) — 대표 입력 1건

마일리지가 상품 잔액과 배송비 **양쪽에 걸쳐** 차감되는 케이스를 대표 입력으로 삼는다
(적용 순서 불변식의 모든 단계가 한 번에 드러난다).

입력
- 라인 1: 단가 12,000원 × 수량 2
- 라인 2: 단가 5,000원 × 수량 1
- 쿠폰 5,000원, 마일리지 26,000원

| 단계 | 계산 | 상품 잔액 | 배송비 잔액 | 비고 |
|---|---|---|---|---|
| 0. 상품 합계 | 12,000×2 = 24,000, 5,000×1 = 5,000 → 24,000+5,000 | 29,000 | (미합산) | |
| 1. 쿠폰 할인 | 29,000 − 5,000 | 24,000 | (미합산) | 쿠폰 전액 사용, 소멸분 0 |
| 2-①. 마일리지 → 상품 | 24,000 − 24,000 | **0** | (미합산) | 마일리지 24,000 사용, 잔여 2,000 |
| 2-②. 마일리지 → 배송비 | 3,000 − 2,000 | 0 | **1,000** | 잔여 마일리지 2,000 전부 사용 |
| 3. 배송비 합산 | 0 + 1,000 | — | — | **최종 결제 금액 = 1,000원** |

- 마일리지 사용액 = 24,000 + 2,000 = 26,000원 (미사용 0원)
- 검증: 최종 1,000원 = 상품 합계 29,000 − 쿠폰 5,000 − 마일리지 26,000 + 배송비 3,000 = 1,000 ✓

부속 검산 (같은 규칙에서 도출되는 경계값 — 위 대표 입력의 마일리지만 변경)

| 케이스 | 마일리지 | 상품 잔액 | 배송비 잔액 | 최종 | 마일리지 사용/미사용 |
|---|---|---|---|---|---|
| 상품 잔액 내에서만 차감 | 10,000 | 24,000−10,000 = 14,000 | 3,000 | 17,000 | 10,000 / 0 |
| 배송비까지 정확히 소진(경계) | 27,000 | 0 | 0 | 0 | 27,000 / 0 |
| 상한 초과(미사용 발생) | 30,000 | 0 | 0 | 0 | 27,000 / 3,000 미사용 |
| 빈 장바구니 (라인 0개, 쿠폰·마일리지 0) | 0 | 0 | 0 | 0 | 배송비도 0원 |

부속 검산 (쿠폰이 상품 합계를 초과하는 경계 — 별도 입력: 라인 1개 단가 3,000원, 마일리지 0)

| 단계 | 계산 | 상품 잔액 | 배송비 잔액 | 비고 |
|---|---|---|---|---|
| 0. 상품 합계 | 3,000 | 3,000 | (미합산) | |
| 1. 쿠폰 할인 | 3,000 − 5,000 → 0에서 정지 | **0** | (미합산) | 쿠폰 초과분 2,000원 소멸 |
| 2. 마일리지 차감 | 0원 사용 | 0 | (미합산) | 마일리지 없음 |
| 3. 배송비 합산 | 0 + 3,000 | — | — | **최종 결제 금액 = 3,000원**(배송비는 쿠폰으로 깎이지 않음) |

### User Story (기능 나열)

#### US-1 — 장바구니 결제 금액 계산 (주 스토리)

    As a    장바구니에 상품을 담고 쿠폰·마일리지를 보유한 고객
    I want  쿠폰과 마일리지가 정해진 순서대로 적용된 최종 결제 금액을 계산해 주기를
    So that 결제하기 전에 내가 실제로 낼 금액을 알고 구매를 결정할 수 있다

- **Valuable**: 결제 전에 실제 부담액을 알 수 있다 — 쿠폰 초과분 소멸처럼 손해가 나는
  조합도 결제 전에 드러난다(사용자 언어).
- **Small**: 부수효과 없는 순수 계산 한 단위. 쿠폰 발급·마일리지 적립/차감 저장·주문
  생성은 이 스토리에 포함하지 않는다.
- **Testable**: 위 검산 전개의 수치가 그대로 기대값이 되므로 단계 2 Gherkin
  `Scenario Outline` + `Examples`로 검증 가능하다(입력 → 최종 결제 금액).

> US-2(금액 구성 내역 확인)는 사용자 확인 결과 삭제됨 — 최종 결제 금액만 반환하고 구성
> 내역(상품 잔액·배송비 잔액·마일리지 사용액)은 노출하지 않는다.

### 범위(Scope) — 사용자 확인 결과

- 이번 tdd-plan은 **원천 문서대로 REST + JPA + MySQL까지 포함**한다(web-app 8단계 템플릿 그대로 진행).
- 입력 유효성은 계산기 책임(위 도메인 규칙의 "입력 유효성" 항목 참조), 외부 상태 의존적
  검증(잔고·쿠폰 유효기간)은 범위 밖.

## 2. Gherkin Scenario

> **숫자의 정본은 §1 "검산 전개"다.** 아래 `Examples` 표의 모든 수치는 그 전개(대표 입력 1건 +
> 부속 검산 표)에서 **옮겨온 파생 뷰**이며 여기서 다시 계산하지 않는다.
> `/cucumber-acceptance` 적용 시 실행되는 원본은 이 Gherkin을 그대로 옮긴 `.feature` 파일이다.
>
> 출력은 **최종 결제 금액 하나**뿐이다(§1: 구성 내역·마일리지 사용/미사용액은 노출하지 않음).
> 따라서 모든 `Then`은 최종 금액 또는 거부 여부만 검증한다.

```gherkin
Feature: 장바구니 결제 금액 계산

  Rule: 적용 순서(상품 합계 → 쿠폰 → 마일리지 → 배송비 합산)가 최종 금액을 결정한다   # ← US-1

    # §1 검산 전개의 대표 입력. 마일리지가 상품 잔액과 배송비 양쪽에 걸치는 케이스로,
    # 적용 순서 불변식의 네 단계가 한 시나리오에 모두 드러난다(happy path).
    Scenario: E-1. 쿠폰과 마일리지가 순서대로 적용된 최종 결제 금액
      Given 장바구니에 단가 12000원 상품이 2개 담겨 있다
      And 장바구니에 단가 5000원 상품이 1개 담겨 있다
      And 쿠폰 5000원을 사용한다
      And 마일리지 26000원을 사용한다
      When 결제 금액 계산을 요청하면
      Then 최종 결제 금액은 1000원이다

  Rule: 마일리지는 상품 잔액에서 먼저 차감되고, 남으면 배송비에서 차감되며, 상한을 넘으면 미사용이다   # ← US-1

    # §1 "부속 검산" 표. 상품 합계 29000 · 쿠폰 5000(→ 상품 잔액 24000) 고정, 마일리지만 변경.
    # 마일리지 사용 상한 = 24000 + 배송비 3000 = 27000 (E-4가 그 경계, E-5가 경계 초과).
    Scenario Outline: <케이스>. 마일리지 차감 범위에 따른 최종 결제 금액
      Given 장바구니에 단가 12000원 상품이 2개 담겨 있다
      And 장바구니에 단가 5000원 상품이 1개 담겨 있다
      And 쿠폰 5000원을 사용한다
      And 마일리지 <마일리지>원을 사용한다
      When 결제 금액 계산을 요청하면
      Then 최종 결제 금액은 <최종금액>원이다

      Examples:
        | 케이스 | 마일리지 | 최종금액 | 걸리는 규칙                                  |
        | E-2   | 10000  | 17000  | 상품 잔액 내에서만 차감(배송비 3000 그대로)       |
        | E-3   | 26000  | 1000   | 상품 잔액 소진 후 배송비에서 추가 차감            |
        | E-4   | 27000  | 0      | 경계: 상한(24000+3000)을 정확히 소진            |
        | E-5   | 30000  | 0      | 경계 초과: 3000은 미사용(결과에 노출되지 않음)     |

  Rule: 쿠폰은 상품 합계에서만 차감되고, 초과분은 소멸한다   # ← US-1

    # §1 부속 검산(쿠폰 초과 경계). 쿠폰 전액이 상품 합계 안에서 소진되는 정상 케이스는
    # E-1이 이미 덮는다. 여기는 "쿠폰이 배송비를 깎지 못한다"가 드러나는 초과 케이스만.
    Scenario: E-6. 쿠폰이 상품 합계를 초과해도 배송비는 깎이지 않는다
      Given 장바구니에 단가 3000원 상품이 1개 담겨 있다
      And 쿠폰 5000원을 사용한다
      And 마일리지 0원을 사용한다
      When 결제 금액 계산을 요청하면
      Then 최종 결제 금액은 3000원이다

  Rule: 배송비는 주문당 고정 3000원이며, 빈 장바구니는 0원이다   # ← US-1

    # 3000원 고정은 E-1~E-6이 이미 덮는다. 여기는 크기 경계(라인 0개)만.
    Scenario: E-7. 빈 장바구니는 배송비도 붙지 않는다
      Given 장바구니가 비어 있다
      And 쿠폰 0원을 사용한다
      And 마일리지 0원을 사용한다
      When 결제 금액 계산을 요청하면
      Then 최종 결제 금액은 0원이다

  Rule: 같은 상품이 여러 라인으로 나뉘어도 상품 합계는 누적으로 계산된다   # ← US-1 (집계 경계)

    # E-1과 상품 구성이 동일하되 12000원 상품만 2개 라인으로 쪼갠 입력.
    # 계산이 라인 단위로만 이뤄지고 누적되지 않으면 여기서 깨진다. 기대값은 E-1과 같아야 한다.
    Scenario: E-8. 같은 상품이 두 라인으로 쪼개져도 결과는 같다
      Given 장바구니에 단가 12000원 상품이 1개 담겨 있다
      And 장바구니에 같은 단가 12000원 상품이 1개 더 담겨 있다
      And 장바구니에 단가 5000원 상품이 1개 담겨 있다
      And 쿠폰 5000원을 사용한다
      And 마일리지 26000원을 사용한다
      When 결제 금액 계산을 요청하면
      Then 최종 결제 금액은 1000원이다

  Rule: 명백히 잘못된 입력은 계산기가 거부한다   # ← US-1 (입력 유효성)

    # 외부 상태 의존 검증(마일리지 잔고·쿠폰 유효기간)은 §1대로 범위 밖 — 여기 없음.
    Scenario Outline: <케이스>. 잘못된 입력 거부
      Given 유효한 장바구니 계산 요청이 준비되어 있다
      And <필드>가 <값>으로 주어진다
      When 결제 금액 계산을 요청하면
      Then 계산이 거부된다

      Examples:
        | 케이스 | 필드    | 값    | 걸리는 규칙        |
        | E-9   | 수량    | 0    | 경계: 수량 < 1     |
        | E-10  | 단가    | -1   | 경계: 단가 < 0     |
        | E-11  | 쿠폰    | -1   | 경계: 쿠폰 < 0     |
        | E-12  | 마일리지 | -1   | 경계: 마일리지 < 0  |
```

### 경계 조건 5종 스캔 결과

| 경계 | 해당 | 시나리오 | 비고 |
|---|---|---|---|
| 수치적 경계 | 해당 | E-4(상한 정확히 소진), E-5(상한 초과), E-6(쿠폰 초과분 소멸), E-9~E-12(0/음수) | 최종 금액 0원 도달, 차감 상한 전후 |
| 크기 경계 | 해당 | E-7(라인 0개) | 라인 수 상한은 규칙에 없음 |
| 상태 경계 | 해당 | E-2(상품 잔액 > 0) ↔ E-3(상품 잔액 = 0으로 전이 후 배송비 차감) | 마일리지 차감 대상이 상품→배송비로 넘어가는 상태 전이 |
| 시간 경계 | **해당 없음** | — | 부수효과 없는 순수 계산이며 타임아웃·유효기간(쿠폰)은 §1에서 범위 밖으로 명시됨. 단, "적용 순서"는 시간이 아니라 계산 순서 불변식이므로 E-1이 담당 |
| 집계 경계 | 해당 | E-8(같은 상품이 두 라인 — 검증/계산 단위가 라인, 반영 단위가 합계), E-3(마일리지 한 자원이 상품·배송비 두 대상에 걸쳐 누적 차감) | 합산되는 자원 = 상품 합계, 마일리지 |

### 제외한 시나리오 (의도적)

- 쿠폰 0원 · 마일리지 0원만 다른 조합, 라인 수만 늘린 변형 → E-1과 같은 규칙 반복
- 마일리지 1원·상한-1원 같은 인접값 → E-4/E-5 경계로 충분(커버리지용 분기는 단계 4 unit test)
- 예외 타입·메시지 검증 → Gherkin은 "거부된다"까지만 고정, 세부는 단계 4 unit test

## 4. Unit Test 목록

> 이 프로젝트는 web-app 유형·acceptance-first 경로다. §2 Gherkin(E-1~E-12)은 이후
> `/cucumber-acceptance`로 `.feature`화되어 external behavior의 주 검증층이 된다.
> 따라서 아래 목록에는 **Gherkin이 이미 검증하는 내용을 unit test로 다시 쓰지 않는다.**
> 다만 RGB 구현 순서(`tdd-red`가 테스트를 선택하는 순서)는 Gherkin 시나리오와 이 절에서
> 새로 추가하는 unit test를 하나의 Degenerate → General 순서로 통합해 아래 "통합 순서"에
> 정리한다 — 물리적 구현 위치(`.feature` vs JUnit)는 다르지만 순서는 하나다.

### 4-1. §2 Gherkin이 이미 덮은 것 (중복 방지 근거 — 여기 다시 담지 않음)

| 규칙 | 덮은 시나리오 |
|---|---|
| 적용 순서 불변식(상품합계→쿠폰→마일리지→배송비), 핵심 happy path | E-1 |
| 마일리지 차감 범위(상품 잔액 내 / 상품+배송비 / 상한 정확히 소진 / 상한 초과·미사용) | E-2~E-5 |
| 쿠폰 초과분 소멸, 쿠폰이 배송비를 깎지 못함 | E-6 |
| 빈 장바구니 → 배송비 0원 | E-7 |
| 같은 상품이 여러 라인으로 나뉘어도 합계는 누적(집계 경계) | E-8 |
| 수량<1 / 단가<0 / 쿠폰<0 / 마일리지<0 — 필드별 단독 위반 거부 | E-9~E-12 |

### 4-2. Gherkin에 없는 세밀 분기 (새로 추가)

- **null 처리 (커버리지 분기)**
    - U-1: 계산 요청 자체가 null이면 거부된다 (공개 API 진입점의 null 방어) — **보류**:
      Walking Skeleton(§5)에서 REST DTO/컨트롤러 진입점이 확정되면 필요 여부 재판단
      (프레임워크가 이미 걸러줄 수 있음)
    - U-2: 라인 목록이 null이면 거부된다 (`§1` "0개 이상의 라인" = 빈 리스트이지 null이
      아님 — E-7과 구분되는 별도 분기)
    - U-3: 라인 목록 안의 개별 라인(또는 그 상품 필드)이 null이면 거부된다
- **여러 예외 조건 동시 성립 시 우선순위 (사용자 결정)**
    - U-4: 수량<1 AND 단가<0처럼 두 개 이상의 필드가 동시에 유효하지 않을 때, **수량 →
      단가 → 쿠폰 → 마일리지 순으로 검사해 가장 먼저 걸리는 위반 하나만 예외로 던진다**
      (전체 위반 목록을 모아 반환하지 않음 — 구현 단순화 우선)
- **무할인 기준선 (E-1로 가는 징검다리)**
    - U-5: 라인 1개, 쿠폰 0원, 마일리지 0원인 정상 장바구니는 상품 합계 + 배송비를
      그대로 반환한다 (할인 로직이 전혀 개입하지 않는 최소 유효 경로 — E-6처럼 마일리지만
      0인 경우와 달리 쿠폰도 0이어서 §2의 어떤 시나리오와도 겹치지 않는다)
- **property-based 후보**
    - U-7: 임의의 (라인 조합, 쿠폰, 마일리지) 입력에 대해 최종 결제 금액은 항상 0
      이상이다 (§1 "최종 결제 금액 ... 항상 ≥ 0" 불변식의 직접 검증 — E-1~E-8은 개별
      수치 하나씩만 확인하므로 이 불변식 자체를 임의 입력으로 스트레스하는 항목은 없음)

> 오버플로 방어(단가·수량 극단값)는 사용자 결정으로 **범위 밖** — 비현실적 입력이며
> `long` 연산 여부와 무관하게 별도 unit test를 두지 않는다.

### 4-3. 통합 RGB 순서 (Degenerate → General, E-1~E-12 + U-1~U-7)

핵심 시나리오(E-1)에서 거슬러 내려가 가장 단순한 케이스(null/빈 장바구니)를 찾고,
E-1 이후로는 집계·기술 도메인·불변식 순으로 일반화해 나간 순서:

- [ ] E-7. 빈 장바구니는 배송비도 붙지 않는다 *(most degenerate — Gherkin)*
- [ ] U-1. 계산 요청 자체가 null이면 거부된다 *(unit)*
- [ ] U-2. 라인 목록이 null이면 거부된다 *(unit)*
- [ ] U-3. 라인 목록 안의 개별 라인/상품 필드가 null이면 거부된다 *(unit)*
- [ ] E-9. 수량 0 → 거부 *(Gherkin)*
- [ ] E-10. 단가 -1 → 거부 *(Gherkin)*
- [ ] E-11. 쿠폰 -1 → 거부 *(Gherkin)*
- [ ] E-12. 마일리지 -1 → 거부 *(Gherkin)*
- [ ] U-4. 여러 필드가 동시에 유효하지 않을 때 우선순위대로 하나의 예외만 던진다 *(unit)*
- [ ] U-5. 라인 1개·쿠폰 0원·마일리지 0원 → 상품 합계 + 배송비 그대로(무할인 기준선) *(unit)*
- [ ] E-6. 쿠폰이 상품 합계를 초과해도 배송비는 깎이지 않는다 *(Gherkin)*
- [ ] E-2. 마일리지가 상품 잔액 내에서만 차감된다 *(Gherkin)*
- [ ] E-3. 마일리지가 상품 잔액 소진 후 배송비에서 추가 차감된다 *(Gherkin)*
- [ ] E-4. 마일리지 차감 상한을 정확히 소진(경계) *(Gherkin)*
- [ ] E-5. 마일리지 차감 상한 초과 — 미사용 발생(경계 초과) *(Gherkin)*
- [ ] E-1. 쿠폰과 마일리지가 순서대로 적용된 최종 결제 금액 *(핵심 시나리오 — Gherkin)*
- [ ] E-8. 같은 상품이 두 라인으로 쪼개져도 결과는 같다(집계 경계) *(Gherkin)*
- [ ] U-7. 임의 입력에 대해 최종 결제 금액은 항상 0 이상이다 *(unit, property-based)*
